# Changelog

Versions 3.0.0–3.2.0 were developed privately under the name **Gauntlet**; the
project was renamed to CrucibleForge before its first public release. Nothing
was ever published as Gauntlet, so there is no migration to do — the entries
below are kept because the engineering they record is real, not to narrate a
rename.

## Unreleased (2026-11-06)

- **Sizing support for MakoBench (below-Q8 and hosted/rented rows).** Board rows
  carry three more facts, travelling like `quant` / `quant_standard`:
  `quant_reason` (`q8_does_not_fit`, from the models.yaml entry key of the same
  name), `served` (`rig` for a local provider, else the entry's `served:` key,
  default `hosted`) and `served_precision` (entry key, e.g. `fp8`, `Q6_K`).
  `bench-all --quant-reason q8_does_not_fit` records the reason when `--only`
  names ONE new registration (refused otherwise). New provider
  `openrouter-q5plus` is `openrouter` plus
  `extra_body.provider = {quantizations: [fp6, int8, fp8, fp16, bf16, fp32],
  allow_fallbacks: false}`, so hosted runs never land on a 4-bit endpoint. Tests
  pin that provider `extra_body` reaches the request body and that
  `bench-all --only X --include-api` plans `judge_only` (no generation) for a
  hosted model whose rows are complete but unjudged. No case content or scoring
  change.

- **Scope alignment.** `bench-all` no longer registers rig models on its own:
  only a model `--only` names (or every in-scope one with `--register-new`).
  Out-of-scope kinds (translation/MT, captioners/OCR, 3D/GLB, TTS/ASR/audio,
  image/video generation, embeddings/rerankers/classifiers/guard/reward) are
  never registered or benched, and a `bench: false` registry row is skipped
  and pruned like a disabled one. A model with a conformance FAIL record is
  **provisional**: its scores stay, it is not ranked (ranks close up, board
  medians leave it out) and `report.json` says `provisional: true` with
  `provisional_reason`. Every row also carries `quant` / `quant_standard`,
  `scope {modalities, text_suite_only}` and `family` (from models.yaml). A
  registry row may set its own `reasoning_replay`; rows made under the other
  setting are regenerated by `bench-all`. No case content or scoring change.

- **`bench-all` can be scoped and run gently (unattended operator support).**
  `--only LABELS` (labels or rig model ids) limits registration, pruning,
  generation, escalation, ladder packs and the judge to those models; a name
  that matches nothing exits 2 instead of widening to the whole board.
  `--lease-mode night` keeps the bench-first policy but never cuts a busy
  resident (`busy_unload_after_s` off); `--lease-mode day` sends no `force`,
  never vacates a render lease, asks priority 3, leases one card that no
  priority-1/2 or pinned model is placed on (refusing otherwise) and implies
  `--no-judge`. `--no-judge` generates only (no judge, no ladder packs, no
  judge reserve in the window). `--plan-json` prints the plan as one JSON
  object (per label: missing cases, estimated generation/judge minutes,
  window verdict). A `keep_on_board: true` registry row is never pruned.
  Detached units stop within 45 s (`TimeoutStopSec=45`, `KillMode=mixed`),
  and the finished run meta carries `exit_code` (and, for bench-all, its
  scope). Without the new flags bench-all behaves as before. No case content,
  scoring or suite revision change.

## 4.0.5 — the conformance gate, the board notes and the protocol stamp (2026-11-03)

(the suite version stays 4.0.1: no case content changed, so no row goes stale)

- **A model is benched only under a request protocol that has been proven for
  it.** `run` and `bench-all` require a conformance record for the CURRENT
  fingerprint (provider type, reasoning replay, extra_body keys, sampler);
  when it is missing or stale the checks run first — for a rig model right
  after it is loaded, for an API model before the run. A **FAIL** means the
  model is **not run**: the run summary, the board and the run report name
  the check that failed (`conformance FAIL: c3`). `--skip-conformance`
  overrides the gate, and the override is logged.
- **Every row records the request protocol it was measured under**
  (`protocol` in the transcript), so a harness fix can tell which rows are
  stale. A model whose board rows mix fingerprints gets the note *"rows
  predate harness change <x> — re-run"* (API models), and `report.md` grows a
  **Conformance** section with each model's verdict and the date it was proven
  on. The board's Notes column says `conformance FAIL: <check>` or a WARN
  summary.
- **The vendor docs of a hosted provider are part of the check** (`c7`): a
  provider row may carry `docs: <url>` and `docs_verified: YYYY-MM-DD`, and
  `conform` WARNs when a hosted provider carries neither, or when the review
  is older than 120 days — the "review the vendor docs" step becomes visible
  instead of being silently skipped.

## 4.0.4 — `conform`: prove the request protocol per model (2026-11-02)

(the suite version stays 4.0.1: no case content changed, so no row goes stale)

- **The bench's request protocol is now proven per model, not assumed.** The
  MiniMax collapse (scores 0.4-1.7) had two causes on the protocol side: the
  reasoning chain was dropped between turns although MiniMax requires it back
  (1/10 recall dropped vs 7/10 replayed), and a retired model id that
  `/v1/models` still listed 404'd on every call. Both were invisible: the
  harness ASSUMED one protocol for every model and never checked it against
  the model's behaviour. `crucibleforge conform` does the check, with a
  handful of cheap calls that go through the bench's OWN request path
  (`Provider.chat` + the runner's message builders) — a hand-rolled request
  would prove nothing, since the point is to exercise the exact bytes and the
  exact conversation the run sends.
  Six checks per model, each PASS / WARN / FAIL with a one-line reason: **c1
  served** (a 1-turn call succeeds; the model the API reports is recorded, so
  an alias is visible; a 4xx is a FAIL), **c2 reasoning** (where the
  reasoning arrives — the `reasoning_content` field, inline `<think>` tags or
  nowhere — and that no think tags leak into the answer, the gemma4 case of
  2026-10-24), **c3 chain** (a 2-turn memory probe whose turn-1 fact exists
  ONLY in the reasoning, run with the current reasoning-replay setting and
  with the opposite one; the opposite recalling better means the replay
  setting is wrong for this model — the MiniMax defect), **c4 tools** (a
  2-step tool round trip through the runner's tool-loop builder; a 4xx or a
  malformed history is a FAIL), **c5 sampler** (the sampler the profile
  would send for this model is accepted) and **c6 budget** (a medium coding
  prompt at the board budget; an empty answer with `finish=length` needs the
  escalation rung, see Room).
  The record lands in `results/conformance/<label>.json` with the protocol
  fingerprint (provider type, reasoning replay, extra_body keys, sampler), so
  a harness change can tell which rows are stale. A rig model is only checked
  while it is loaded — `conform` never loads a model behind the bench's back
  (`--allow-load` does, under the rig lock).
- **`runner.assistant_turn` is now the one builder for the assistant turn**,
  shared by the multi-turn runner and the conformance probe, so a probe can
  never measure a conversation the bench does not send.
## 4.0.3 — case lint: one requirement per judge element (2026-11-02)

- **`cases verify` now rejects a COMPOUND judge element** (the root cause
  behind the NC3 heat verdict). A judge element is ONE YES/NO: the judge
  answers the whole question, so a question that chains several
  requirements ("is the sex written explicitly on the page, AND does she
  come, AND does he say her name?") turns a PARTIAL miss into a full NO —
  and a NO caps the element's dimension (`cap`, default 3) or flips its
  flag, which is how NC3's turn-6 peak element asked four things at once
  and capped the heat of a reply that wrote the scene but not the name
  (43c7483 split that element; this lint stops the next one).
  `judge.GATING_DIMS` names the dims whose element failure gates a score
  (`explicitness`, `constraints`, `continuity`, `identity`, `integrity`,
  `character`, `voice`, `obeyed`); an element on one of them whose question
  joins more than two requirements is an ERROR. The count is of REQUIREMENT
  joins: a conjunction that opens a new clause ("AND does she come", "while
  he says her name") joins two requirements, while one that coordinates
  words inside one requirement ("her tongue, what she does with her hand",
  "hands and knees") does not, and neither does a parenthetical aside.
  The whole shipped case set passes the lint (463 judge elements over 393
  cases); the pre-fix NC3 text is kept as the regression fixture in
  `tests/test_case_lint_compound_20261102.py`. No case content changed, so
  the suite hash (`e3d1c6fb`) and every stored row are untouched.

## 4.0.2 — MiniMax: the reasoning chain goes back (2026-11-02)

- **The reasoning chain is no longer dropped on the floor (provider-gated).**
  MiniMax documents that the complete assistant message — `reasoning_content`
  included — must be appended to the conversation history or the chain is lost
  ("the complete model response (i.e., the assistant message) must be append
  to the conversation history to maintain the continuity of the reasoning
  chain", platform.minimax.io/docs/api-reference/text-openai-api). The runner
  fed back the CONTENT channel only, so the thinking was discarded: measured
  1/10 recall with the chain dropped against 7/10 replayed, and the model
  produced reasoning on 1 of 12 turns instead of 6–12 of 12 (the harness was
  not merely losing information, it was suppressing the model's thinking).
  A new per-provider switch `providers.<name>.reasoning_replay` turns the
  protocol on: the assistant turn goes back with its `reasoning_content`, and
  every request to that provider carries `reasoning_split: true` so the
  thinking arrives in that channel for EVERY model on it (M3.1-Flash, M3,
  M2.x — accepted by all six; M3.1-Flash requires it). The judged
  conversation stays content-only — the CoT is the model's context, not its
  answer. **Default: on for a provider pointed at MiniMax's API
  (api.minimax.io / api.minimaxi.com), off for every other provider**; off
  means every request is byte-identical to a run without the switch, which a
  golden capture of the deepseek and studioforge request bodies proves.
- **The tool loop keeps a well-formed history at a prose step.** When the
  model called a tool where the case wanted prose, the harness appended the
  assistant turn *without* its `tool_calls` and without any tool result: the
  model's unanswered request leaked into the next turn and was re-issued
  there, which then failed "N tool calls, expected 1" (45 calls dropped
  across the stored transcripts, 3/3 of those failures a re-issue). With the
  replay on, the calls stay on the assistant turn and EVERY one is answered,
  so the next request is well-formed. The step itself still fails — the case
  wanted no tool — but the conversation no longer leaks.
- **MiniMax facts, now documented where providers are configured:** the API
  **ignores `temperature` and `top_p`** (it always uses 1 / 0.95); **M2.5 and
  M2.7 retire on 2026-11-18**; and M Plan / Token Plan traffic to M2.5 /
  M2.7 is **auto-routed to M3.1 Flash** from 2026-10-19, which CF cannot
  detect (the `/v1` response carries the *requested* model id). `models.yaml`
  is the maintainer's and is untouched by this change; the switch is
  documented in `models.example.yaml` and the README.

## 3.10.0 — lock-in round: harness (2026-10-30)

- **Currency is per row and per case.** A row counts when it was made under the current regime (suite
  version compared as a tuple, so 3.10.0 > 3.9.0) and answers the current content of ITS case
  (`version.case_hash`). Editing one question re-runs only that question's rows; the SUITE_VERSION bump
  to 3.10.0 re-runs nothing. Rows from before 3.10 are matched case by case through a frozen snapshot
  (`crucibleforge/stamps/3.9.0+ba6eb461.json`); rows on disk are never rewritten.
- **Grading edits re-judge, they do not re-generate.** A change to a case's judge elements, card
  summary, willingness switch or metric tags (`version.grading_hash`), or a policy asking a row for more
  judge samples, re-judges the stored transcript in the next `judge` / nightly run. Check and tool-step
  needle edits apply at report time. `bench-all` prints, per model, what it would regenerate and what it
  would only re-judge.
- **Rig code-bank rows served below the 73,728 bank window are re-run** (their answers were cut by the
  server, not by the bank budget).
- **A sub-score with an excluded row says so:** "partial (n excluded)" on the points board and in
  report.json (`headline.excluded`), never MAXED. The nightly already retries unparsable verdicts once.
- **Ladder:** the easy leftover packs (NSFW writing set 1, Deep RP set 1) sit on the same level as the
  hard pack beside them, so they no longer gate it. A pack holds at least 3 questions unless it says
  `"allow_small": true` with an `"allow_small_reason"`. A broken pack file is skipped with an error instead
  of taking down the case set, the board or `bench-all`; `cases verify` reports it.
- **Creative writing:** a second standard session, WR2 (co-writing, craft elements at half its weight);
  WR1's three craft elements now carry half of WR1's weight.
- **Same-family judge warning** reads the registry (`family:`, `arch:` — `bench-all` records the rig's
  architecture when it registers a model) and model ids, never the label. The board footnote says which
  sub-scores rest on one or two cases (their ± is the bootstrap floor).

## 3.9.0 — review fixes (2026-10-29)

- **`bench-all --until` is a hard end, judge included:** each model is admitted only if its estimated
  generation fits; the judge reserve comes from the estimate (`--judge-reserve-min` is the floor); rows
  in flight at the stop get 10 minutes, then they are dropped and stay pending. The judge stops before
  the cut, and on SIGTERM, without reloading. An `--until` more than 14 h away is refused, so a day run
  launched after its end time doesn't run until tomorrow.
- **bench-all runs due ladder packs**, and a due pack keeps the nightly from marking itself done.
- **Failed means failed everywhere:** errored jobs, judged ones included, and jobs that ran out with no
  finished re-run score 0. Sessions count as one unit in Efficiency and in errored n/N.
- **Partial runs are not extrapolated:** Overall shows "-", the model is unranked, and a "partial (n/N
  cases)" note appears.
- **The public board never reads private ladder packs.**
- **The judge lease never names GPU 3.** A judge or model lease marks the rig touched, so evicted
  residents are restored. An API-only run never reloads a rig resident.
- **A stream dropped before a finish_reason or usage is a transport failure, not an answer.** SSE
  edge cases are fixed.
- **`--first` runs the models in the order given.**

## 3.8.0 — measure models as deployed (2026-10-24)

A review of the bench asked whether the board measures typical performance.
It did not: every coding and steer case ran at temperature 0 (vendors advise
against greedy decoding for thinking models, and no production client sends
it), hosted APIs got a 65k thinking budget where rig models got 24k, and a
thinking run that ran out of budget was silently re-asked with thinking OFF and
graded at full credit (71% of the rig thinkers' Programs rows, 47% of Instruct;
those retries passed Instruct 34% of the time against 83% for real thinking
rows). The profile now declares `regime: deployed`:

- **Sampler:** no `temperature`/`top_p` is sent for the model under test — the
  server's or vendor's default applies, as for every production client. A
  registry entry may pin `sampler: {temperature, top_p}` where production does.
  The judge is unchanged (temperature 0).
- **Thinking:** the chat template's default (unchanged — the bench never sent
  a thinking switch on the first try).
- **Budget:** the profile's cap (24576) for every provider; per-provider
  overrides are ignored. A thinking model gets at least
  `thinking_max_tokens_floor` (16384) so short chat cases do not starve it.
- **No thinking-off retry** (`reasoning_overflow_recovery: false`): an answer
  that never arrives is scored as missing, and the report counts them.
- **Empty chat replies score 0** on every judged dimension (they were dropped
  from the averages, which rewarded running out of budget). Rows of older
  suites keep their old rule.
- **3 repeats** for programs, tools, instruct, reasoning and math: with
  sampling, one row per case was a coin flip (one Programs case moved Coding
  ~11 points).
- **Regime stamp:** every row and meta carries `regime`, `reasoning_format`,
  `thinking` and `sampler`.

`SUITE_VERSION` 3.8.0 is deliberately NOT equivalent to the 3.4.0–3.7.0 stamps
of the same case set: those rows answered the same prompts under different
rules. **The board keeps them, marked:** a model whose 3.8.0 run is not yet
complete and judged shows its previous values with "(old)" in the new **Suite**
column (report.md and report.html; old rows are dimmed) and "re-run n/m cases"
in Notes. `bench-all` plans only from current rows, counts a case done only
when every repeat is there, ignores errors of older suites when capping
retries, and takes `--until HH:MM` / `--judge-reserve-min` to fit a nightly
window (generation stops cooperatively, the judge and both boards still run,
the rest waits for the next night).

### Recommended sampler per model (2026-10-25)

- "As deployed" now means the maker's recommended sampler, not "send nothing":
  `profiles/bench.yaml` `recommended_samplers` (first regex match on
  `<provider>:<model_id>` or the label; a registry `sampler:` still wins).
  Each rule names its source (model card / vendor docs). Why: llama-server
  takes temp/top_p/top_k from a GGUF's `general.sampling.*` keys, but no file
  on the rig sets `min_p`, so its built-in 0.05 ran where Qwen and Gemma say 0,
  and Qwen's `presence_penalty` has no GGUF key at all. Fine-tune cards that
  publish their own values (Dark-Scarlett, ReadyArt Gemma, Split-Untied,
  Artemis, Loki-Scotoma, Orion, JoyFox) get them. Hosted APIs fix or ignore
  their sampler (DeepSeek thinking mode, MiniMax, Kimi): nothing is sent, so
  the 3.8.0 API rows stay current. Rows stamp `sampler` with the rule id.
- The link-check probe, the thinking probe and the perf warm-up send the run's
  sampler instead of `temperature=0` — kimi-k3 refuses any temperature but 1
  and aborted before its first case.

### Review fixes (Fable review, 2026-10-25)

- **Tool cases ran off-sampler.** The tool loop never passed the model's `top_p`, so every tool
  request went out with the API default 1.0 instead of the model's recommended value (or none).
  Kimi refuses anything but 0.95: 18 of its 21 tool rows errored and were left out, so its Tools 100
  rested on 3 rows. Tool rows now send the same sampler as every other row and stamp the budget they
  really sent. Every model's Tools number may move on its next run; the Kimi rows need a re-run.
- **The escalation round converges.** A rung the rig cannot serve (a refusal that the context does
  not fit) is given up at once, a rung that fails twice since the model's last board run likewise
  (`runner.blocked_rungs`; a STOP or window edge does not count). `bench-all`'s plan, `escalate` and
  the Room "pending" count all use the highest rung still open, so the nightly's done-check can no
  longer stay open forever. Escalated rows still waiting for the judge keep Room marked "…".
- **Old values rank below current ones.** A model still on pre-3.8 values ("(old)") used to be
  ranked by its old Overall against 3.8 numbers; the regimes are not comparable, so old rows now sit
  under every current row.
- **Orphaned run reports.** A run killed without SIGTERM left its report "running" forever. Reports
  now record the pid and host; the next run marks one whose process is gone as failed.
- **New board notes:** replies stuck in the reasoning channel (finished without closing the think
  block) are counted apart from answers that ran out of budget, and a model served with a context
  smaller than its output budget gets a warning (gemma-26b-qat: 8192).
- Room's footnote says the wide reload may drop the KV cache to q8_0.

### Escalation round and the Room column (2026-10-25)

The board budget (24576 output tokens) is the same for every model, so it
measures "solves it within 24k". A long thinker that needs 60k tokens on a hard
program scored 0 there, and running a whole bench at 128k costs slots: 6
instead of 8 for a 27B, and only one of 120 jobs needed it on one model
(21 on another).

- After a run, every job whose answer ran out of budget (thinking model,
  `finish=length`) is re-run at 65536 tokens, and whatever still runs out at
  131072. The model is reloaded with a context wide enough for the rung, so
  fewer parallel slots, and only for those jobs. Profile key:
  `escalation_rungs` (bench: `[65536, 131072]`; `[]` = off).
- Those rows carry `budget_rung` and never count on the board.
  `board_filter(..., with_rungs=True)` is the Room view: the newest run of
  each job, an escalation included.
- report.md gets a **Room** column after Overall: Overall with the escalated
  jobs swapped in. `=` means nothing ran out; `…` means a re-run is still
  pending. The HTML board offers it in the column chooser.
- Runs by default in `all` and `bench-all`, between generation and the judge,
  inside the `--until` window; skip it with `--no-escalate`. A standalone
  `crucibleforge escalate [--models] [--rungs]` exists too. The bench-all plan
  prints `> escalate …`, and the nightly isn't done until that's empty.
- An escalation failure is logged and noted but doesn't change the run's exit
  code (the board run itself is complete). A rung the rig can't serve wide
  enough is refused, never cut short.
- Fix: a re-run whose timestamp matched the earlier run's (one-second
  resolution) lost the "newest run" tie. Ties now go to the row written later.

### Also in 3.8.0
- **Thinking models on the rig always get their reasoning separated.**
  StudioForge launches models with `--reasoning-format none`, so thoughts
  arrive inline in `content`; the bench only coped when a registry entry set
  `extra_body.reasoning_format` or it knew the model's tag dialect. Three
  gemma4 models (`<|channel>thought … <channel|>`) had neither: the tags
  leaked into graded answers, the models were never classified as thinking
  (no ×4 budget) and most rows truncated, so Programs/Instruct/Reason read 0.
  Now (1) the runner requests `reasoning_format` (`defaults.rig_reasoning_format`,
  default `deepseek`) for every rig model whose listing says `thinking`;
  (2) `api._THINK_TAGS` understands gemma4's channel dialect (including the
  empty channel `enable_thinking: false` still emits on the recovery rung);
  (3) `bench-all` registers gemma4 rig models with the flag; (4) any
  special-token marker (`<|…>`, `<…|>`) that still reaches an answer is
  counted and written to the model's meta as a warning — its scores measure a
  parsing gap, not the model.

## 3.7.0 — GUI token management and lockout recovery (2026-10-19)

No case, grader or metric changed. `SUITE_VERSION` moves to 3.7.0 with the
package and the 3.6.0 stamp of the same case set (`36a60ec6`) is registered as
equivalent in `_EQUIVALENT_STAMPS`, so no stored board row goes stale.

CrucibleForge has no users or passwords; its one login is the GUI access
token, and until now a lost token meant editing process arguments or compose
files. New:

- **`crucibleforge gui token show | rotate [--token-stdin]`.** The token is
  stored in `<data dir>/gui_token` (mode 0600; the data dir is the folder of
  `models.yaml`, printed on every call). `gui` start-up picks `--token`, then
  `CRUCIBLEFORGE_GUI_TOKEN`, then the file. The token is never a command-line
  argument for the new verbs (`--token-stdin` reads it from stdin). They work
  even when `models.yaml` itself is invalid. Docker form:
  `docker compose exec app crucibleforge gui token show`.
- **`<data dir>/RESET_LOGIN` sentinel.** Read once, at `gui` start-up and before
  the port is bound, by someone with filesystem access to the data dir: an
  empty file makes a random new token, a file with text uses it. It is deleted
  first (an undeletable, oversized, symlinked or malformed sentinel is never
  acted on), so it cannot replay; one log line names the file, never the
  token. No HTTP endpoint touches it (pinned by a structural test).
- **A configured or stored token is never written to the log.** The start-up
  line `CrucibleForge GUI: ...?token=` carries the token only when it was
  generated on that start (off-loopback, none configured); a token from
  `--token`, `CRUCIBLEFORGE_GUI_TOKEN` or `gui_token` is announced by source
  only (container logs outlive the process). `gui token show` prints it.
  The Docker entrypoint no longer appends `--token $CRUCIBLEFORGE_GUI_TOKEN`
  to the command line (it showed in `ps` and broke `gui token show`); the GUI
  reads the variable itself, so a variable in `crucibleforge.local.env` or
  the shell now also puts a token on the loopback GUI. An existing but
  unreadable or invalid `gui_token` is reported, not silently ignored.
- README "Accounts and lockout recovery" and the Docker docs have copy-paste
  commands for Windows, macOS, Linux and Docker. `gui_token` and `RESET_LOGIN`
  are git- and docker-ignored.
- **GUI "Judge pending rows" uses the benchmark's judge.** `/api/judge` passed
  no judge, so `run_judge` walked `judge.candidates` and scored the rows with
  a model whose verdicts do not count on the board; it now takes the bench
  profile's judge and budgets, as `crucibleforge judge` does (an explicit pick
  in the judge menu still wins). The dashboard names the benchmark judge
  above the fallback candidates.

## Unreleased — cross-platform correctness and the sandbox default

- **BREAKING (macOS/Windows): grading refuses to run without a sandbox.**
  `bwrap` is Linux-only, so on macOS — a leg of this project's own CI matrix —
  and on any Linux box without bubblewrap, every coding case and
  `cases verify` used to execute model-authored Python with no isolation:
  network reachable, home directory readable, and nothing in the log to say
  so. A warning would not have changed what ran, only when you found out. The
  default is now to stop, before a run starts rather than at the first coding
  case. `--allow-unsandboxed` (or `CRUCIBLEFORGE_ALLOW_UNSANDBOXED=1`) opts in
  deliberately, and warns once when it does.
- **Case-insensitive filesystems.** A model's name IS a filename
  (`transcripts_<name>.jsonl`), so two names differing only in case resolve to
  one file on APFS/NTFS and two models' rows merge into a chimera the report
  then scores. Rejected in `validate_config`, where Linux can catch it.
- **Explicit UTF-8** on every text read/write and subprocess pipe that carries
  model output: transcripts are written `ensure_ascii=False`, so the platform
  default was a guaranteed `UnicodeEncodeError` on a cp1252 Windows box and
  mojibake on read-back.
- **pre-push scans the tree of every outgoing commit**, not only the tip. A
  secret added in commit N and removed in N+1 published unnoticed.

- **`load-recommended` is satisfied by a bad resident.** It treats "already
  loaded at that context" as done and returns the *existing* plan, so a
  leftover JIT load (serial, on the slow cards) survived into a full
  benchmark run on 2026-08-24. A degenerate resident (1 slot / short context)
  is now unloaded first so the server re-plans it.
- **A pinned idle resident blocks the lease**: retried with `force: true`
  only in that case — the rig's pin reconciler restores the pinned model
  after the lease is released. Busy residents are still never forced.
- **Restore** unloads what the run loaded before reloading the prior
  residents, instead of asking the rig to hold both at once.
- **SIGTERM releases the lease.** A killed queue used to leave the cards held
  until the TTL expired.
- **`answered_in_reasoning`**: a tool call with empty `content` is an answer,
  not a misrouted reply — this was stamping false "read from reasoning" notes
  on perfectly good tool-use rows.
- `scripts/clawforge_comfy.py`: free rig VRAM (ComfyUI) before a phase.
- `scripts/queue-overnight.sh`: the reference campaign wrapper (flock on
  `results/.rig.lock`, env sourced in-shell for the lease PIN, run→judge per
  model, one report, rc checked per phase).
- Docs: README case counts corrected to the real 251 / 158 hard and the
  56-case `standard` profile.

## 3.2.0 — 2026-08-22 (evening)

Second revision from the campaign postmortem: a swarm review (5 lenses, every
finding adversarially verified — 39 confirmed) plus the rig's own
`BENCHMARKING.md` playbook, re-checked against the live StudioForge 0.2.0 API.

- **Rig etiquette / GPU leases** (`studioforge.py`, `providers.py`): with
  `lease: true` a run takes `POST /api/leases` on the configured cards (holder
  `crucibleforge`) for the benched model and again for the judge, keeps it alive,
  releases it on exit; busy residents are *waited for* (`wait_busy_s`), never
  evicted, never `force`d (the old client unloaded everything and sent
  `force: true` — the one client on the box that could rip a chat-tier
  model out mid-reply); evicted residents are reloaded at the end
  (`restore_residents`); the `X-MCP-Pin` header reaches every management call
  (`${ENV}` in `headers`). `507`/`503` bodies are read: `retry_after_s` is
  honoured (`api.VramContention`), per-mode `suggestions` are surfaced, and a
  window that does not fit is an error — never a silent JIT load at planner
  defaults. Placement profiles use the 0.2.0 nested `optimal` shape and keep
  `devices`. Eviction detection: `is_loaded()` compares the live plan (slots,
  ctx, devices) with the one the run loaded. `wait_ready()` tolerates
  transient status errors and gives up after 60 s when the model never
  appears. `crucibleforge status` prints residents + leases.
- **Runner**: a recovered TOOL CALL counts as recovered; a failed recovery
  request keeps the honest first result and does not count toward the
  transport-abort; every attempt is billed on the row (cost/tokens);
  `chat_template_kwargs` merge one level deep; a negative thinking probe no
  longer disarms auto-detect (gemma-e4b ran every case on the raw budget);
  `reasoning_format` in `extra_body` means thinking. A model-local abort no
  longer sets the global STOP (the rest of the batch used to be skipped
  silently). **Graders never harvest an answer from truncated reasoning**
  (finish=length): 9 of one model's 51 coding "passes" were code dug out of
  100k chars of cut-off chain-of-thought that no user ever received. The
  registry/live context mismatch is detected and long-context cases skipped
  honestly. `crucibleforge recover` re-runs each (run, case, repeat) triple, logs
  unselectable jobs, never rewrites the run's meta (appends `recovered`).
- **Judge**: per-row isolation (`RequestRejected`/`GenerationRejected` → a
  failed verdict without a reload; any other error → counted `errored`, row
  left for a re-run; reload guarded by a lock and skipped when another worker
  already restored the judge); a thinking judge that reasons its budget away
  is re-asked with thinking off; failed verdicts keep `judge_finish_reason`/
  tokens/reasoning tail; a judge failure on a reference row leaves the row
  **pending** instead of failing the model.
- **Revision/judge stamp**: `bench_revision` now hashes the test set only;
  the primary judge's measurement settings are a separate
  `judge_fingerprint`; rows stamped with the pre-3.2 combined hash stay
  current while nothing changed (`legacy_revision`).
- **Report**: Coverage ranks full-suite runs scored by the configured judge
  first; partial / profile / stale / differently-judged / failed rows are
  labelled (with `attempted`/`n/a` counts) and ranked below; new **Judge**
  column (`self` for self-graded reference rows); Summary table carries
  Coverage and the scorecard order; a one-half Total says "(Code only)";
  Willing counts empty replies as unwritten and every rate cell shows
  (scored/total); family-overlap note compares each model with *its* judge.
- CLI exit codes: `run`/`recover` are non-zero when any requested model
  failed or never ran; `judge` when rows errored. Queue scripts stamp DONE
  only on clean exits and serialise on a lock.

## 3.1.0 — 2026-08-22

Root-cause fixes from the first full-board campaign (seven 251-case runs).

- **Reasoning-overflow recovery**: a thinking model that spends its whole
  budget in the reasoning channel (finish=length, empty content — 27–45 rows
  per model, 10–18 % of a score) now gets its answer recovered on the case
  budget: `chat_template_kwargs: {enable_thinking: false}`, then a
  continuation of the truncated reasoning. Rows record `reasoning_overflow` +
  `recovery` (mode, attempts, first-attempt cost); the report counts them.
  New `crucibleforge recover` re-runs only those rows of existing transcripts
  (same `bench_run_id`, so they supersede) ready for `crucibleforge judge`.
- **Per-case failure isolation**: llama-server 500 "Failed to parse tool call
  arguments" (the model's own malformed output) is `GenerationRejected` — not
  retried, scored as that case failing; other transport errors write an error
  row and abort the model only after 3 in a row. Previously one such 500
  aborted the entire model run (joyfox-35b-rp, twice).
- **Strict forced judge**: `--judge` is retried on `judge.load_retry_s`
  (VRAM contention from a co-tenant on the rig is transient) and then fails
  loudly; it no longer silently scores a model with the next candidate
  (which broke the single-judge rule and mixed judge families on the board).
  `--judge-fallback` opts back in.
- **Judge counts**: "parse-failures" no longer includes empty generations;
  the two are reported separately (`failed` vs `empty`).
- **Coverage on the scorecard**: complete runs rank first; partial (smoke /
  category-filtered / hard-only), FAILED and stale-revision rows are
  labelled and ranked below, whatever their Total.
- **StudioForge readiness**: after an explicit load the client waits for the
  engine to report `ready` before the warm-up completion (a warm-up sent
  during `loading` made the server plan a second load that then 507'd).
